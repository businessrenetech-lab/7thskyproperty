SEVENTH SKY CRM – HRM SYSTEM

MODULE 1: ORGANISATION STRUCTURE
Functional Requirements Specification – Step 1

1. Purpose
The Organisation Structure module will allow Seventh Sky to create, manage and update the full company structure inside the CRM.
This module must support:
	•	Seventh Sky Pty Ltd - with
	•	Multiple divisions – Here for Seventh Sky Property Care
	•	Multiple departments
	•	Multiple branches
	•	Multiple teams
	•	Job positions
	•	Reporting lines
	•	Managers and supervisors
	•	Cost centres
	•	Future business expansion

2. Business Requirement
Seventh Sky Property Care will operate multiple service divisions, including:
	•	Residential
	•	Commercial
	•	Rural 
	•	Business 
	•	Interior Design 
	•	Property Care & Concierge 
	•	Leasing & Tenancy Management 
	•	Removal & Relocation Services
	•	Property Documentation Support 
	•	Solar & Energy Solutions 
	•	Air Conditioning Solutions
	•	Water Tank Cleaning & Maintenance Services 
	•	Finance
	•	HR
	•	Marketing
	•	IT
	•	Administration
The HRM system must allow Seventh Sky management to add, edit, deactivate or restructure departments without developer support.

3. Required Organisation Hierarchy
The CRM should support the following structure:
Seventh Sky Private Ltd → Division → Department → Team → Position → Employee
Example:
Seventh Sky Private Ltd → Property Care Division → Removal & Relocation Department → Operations Team → Relocation Coordinator → Employee Name

4. Required Features
4.1 Company Profile
The system must allow management to create and manage:
	•	Company name
	•	Trading name
	•	Registration number
	•	TIN
	•	BIN
	•	Address
	•	Contact details
	•	Logo
	•	Business divisions
	•	Branches
	•	Company policies

4.2 Division Management
The system must allow creation of divisions such as:
	•	Seventh Sky Property Care  (www.seventhskypropertycare.com)
	•	Seventh Sky Global Education & Migration (www. seventhskyeducationandmigration.com)
	•	Seventh Sky Training & Workforce Solutions (seventhskyworkforcesolutions.com)
	•	Seventh Sky Café & Lounge (seventhskycafe.com)
Each division should include:
	•	Division name
	•	Division head
	•	Division code
	•	Business function
	•	Active/inactive status

4.3 Department Management
Each division may contain multiple departments.
	•	Residential
	•	Commercial
	•	Rural 
	•	Business 
	•	Interior Design 

Department fields:
	•	Department name
	•	Department code
	•	Division
	•	Department manager
	•	Location
	•	Cost centre
	•	Active/inactive status

4.4 Position Management
The system must allow HR to create job positions.
Position fields:
	•	Position title
	•	Position code
	•	Department
	•	Reports to
	•	Employment type
	•	Salary grade
	•	Job description
	•	Required qualifications
	•	Required experience
	•	Required skills
	•	Approval authority
	•	Active/inactive status

4.5 Reporting Line
The system must show:
	•	Direct supervisor
	•	Department manager
	•	Division head
	•	CEO
Each employee profile must display who the employee reports to.
Managers must be able to view employees reporting to them.

5. Organisation Chart
The CRM must generate a visual organisation chart showing:
	•	Company
	•	Divisions
	•	Departments
	•	Managers
	•	Positions
	•	Employees
The organisation chart should be filterable by:
	•	Division
	•	Department
	•	Branch
	•	Position
	•	Manager
	•	Employment status

6. Approval Workflow
Changes to organisation structure should follow approval steps:
Request created by HR ↓ Reviewed by HR Manager ↓ Approved by CEO ↓ System updated ↓ Change recorded in history log
Examples requiring approval:
	•	New department
	•	New position
	•	Position deletion
	•	Reporting line change
	•	Salary grade change
	•	Department restructure

7. Access Control
Suggested access permissions:
Role
Access
CEO
Full access
HR Manager
Create/edit organisation structure
Department Manager
View own department
Finance Manager
View cost centre and salary grade
Employee
View basic organisation chart only

8. Reports Required
The system should generate:
	•	Organisation Structure Report
	•	Department List
	•	Position List
	•	Reporting Line Report
	•	Vacancy by Department
	•	Headcount by Division
	•	Headcount by Department
	•	Active/Inactive Position Report
	•	Cost Centre Report

9. Automation Requirements
The system should automatically:
	•	Assign department code
	•	Assign position code
	•	Update employee reporting line
	•	Notify affected managers when structure changes
	•	Record structure change history
	•	Alert HR if a position has no assigned supervisor
	•	Alert HR if a department has no manager

10. CRM Integration
This module must connect with:
	•	Employee Master Database
	•	Recruitment
	•	Onboarding
	•	Attendance
	•	Leave
	•	Payroll Preparation
	•	Performance Management
	•	Training
	•	Reports & Dashboard
No employee should be created without being linked to:
	•	Company
	•	Division
	•	Department
	•	Position
	•	Supervisor

RENETECH must design this module in a way that Seventh Sky can change, expand or restructure the company internally without needing developer support.
The system must be scalable enough to support at least:
	•	10 Trading business under Seventh Sky Property Care
	•	50 divisions
	•	100 departments
	•	1,000 positions
	•	5,000 employees














MODULE 2: EMPLOYEE MASTER DATABASE
Functional Requirements Specification – Step 2

1. Purpose
The Employee Master Database will be the central record for every person working with Seventh Sky.
This module must store complete employee information and connect with all other HRM modules, including:
	•	Recruitment
	•	Onboarding
	•	Attendance
	•	Leave
	•	Payroll Preparation
	•	Performance
	•	Training
	•	Compliance
	•	Documents
	•	Reports
No employee should be active in the CRM unless their Employee Master Record is created.

2. Employee Types
The system must support different worker types, including:
	•	Full-time employee
	•	Part-time employee
	•	Casual employee
	•	Contract employee
	•	Intern
	•	Consultant
	•	Remote worker
	•	Field staff
	•	Probationary employee
	•	Third-party assigned worker
	•	Temporary worker
Each employee type may have different rules for attendance, pay, benefits, leave and document requirements.

	•	Nationality
	•	Personal Mobile
	•	Personal Email

Fields:
	•	Present Address
	•	Permanent Address
	•	City
	•	District
	•	Postal Code
	•	Country
	•	Emergency Contact Name
	•	Emergency Contact Relationship
	•	Emergency Contact Phone
	•	Emergency Contact Address

Fields:

	•	Position

MODULE 3 – RECRUITMENT & APPLICANT TRACKING SYSTEM (ATS)
Functional Requirements Specification – Step 3

1. PURPOSE
The Recruitment & Applicant Tracking System (ATS) shall enable Seventh Sky to manage the complete employee recruitment lifecycle from workforce planning through to onboarding.
The module shall:
	•	Reduce recruitment time. 
	•	Standardise recruitment procedures. 
	•	Improve candidate quality. 
	•	Maintain recruitment compliance. 
	•	Build a talent pool. 
	•	Automate recruitment workflows. 
	•	Provide recruitment analytics. 
This module must integrate seamlessly with:
	•	Organisation Structure 
	•	Employee Master Database 
	•	Onboarding 
	•	HR Dashboard 
	•	Performance Management 
	•	Payroll Preparation 

2. RECRUITMENT WORKFLOW
The CRM shall support the following recruitment workflow:
Workforce Planning  ↓  Vacancy Request  ↓  Management Approval  ↓  Job Advertisement  ↓  Applications Received  ↓  CV Screening  ↓  Shortlisting  ↓  Interview  ↓  Assessment  ↓  Reference Check  ↓  Final Approval  ↓  Offer Letter  ↓  Offer Acceptance  ↓  Pre-employment Documents  ↓  Onboarding  ↓  Employee Master Database
Every stage must be visible on a recruitment dashboard.

3. WORKFORCE PLANNING
Before creating a vacancy, managers should submit a Workforce Request.
Required information:
	•	Department 
	•	Position 
	•	Reason for recruitment 
	•	New Position / Replacement 
	•	Number of vacancies 
	•	Proposed salary range 
	•	Employment type 
	•	Expected joining date 
	•	Budget availability 
	•	Approving Manager 

4. VACANCY REQUEST
Required fields
	•	Vacancy ID 
	•	Department 
	•	Position 
	•	Reports To 
	•	Employment Type 
	•	Salary Grade 
	•	Location 
	•	Number of Positions 
	•	Closing Date 
	•	Recruitment Priority 
Priority options:
	•	Critical 
	•	High 
	•	Normal 
	•	Future

Department Manager
↓
HR Manager
↓

↓

↓
Vacancy Published

	•	Date 
	•	Time

	•	Position title

	•	Experience

	•	Qualification Verification 
	•	Professional Licence Verification 
	•	Police Clearance (if required) 
	•	Medical Assessment (if required) 
	•	Right to Work Verification

Offer details:
	•	Position 
	•	Salary 
	•	Employment Type 
	•	Probation Period 
	•	Start Date 
	•	Supervisor 
	•	Work Location

Candidates should be able to accept electronically.

	•	Position 
	•	Experience 
	•	Education

	•	Availability

17. AUTOMATION REQUIREMENTS
The CRM should automatically:
	•	Generate Vacancy ID 
	•	Generate Candidate ID 
	•	Send acknowledgement email 
	•	Schedule reminders 
	•	Notify interview panel 
	•	Generate offer letter 
	•	Transfer successful candidates to Onboarding 
	•	Archive unsuccessful candidates 
	•	Update recruitment dashboard 

18. RECRUITMENT REPORTS
The CRM should generate:
	•	Recruitment Pipeline Report 
	•	Vacancies by Department 
	•	Time to Hire 
	•	Cost per Hire 
	•	Source of Candidates 
	•	Interview Success Rate 
	•	Offer Acceptance Rate 
	•	Recruitment Status Report 
	•	Talent Pool Report 
	•	Vacancy Age Report 

19. HR RECRUITMENT DASHBOARD
Display:
	•	Open Vacancies 
	•	Applications Received 
	•	Candidates Shortlisted 
	•	Interviews Scheduled 
	•	Offers Pending 
	•	Offers Accepted 
	•	Vacancies Filled 
	•	Average Time to Hire 
	•	Recruitment Cost 
	•	Candidate Sources 
	•	Talent Pool Size 

20. AI FEATURES (HIGHLY RECOMMENDED)
RENETECH should build AI-assisted recruitment tools, including:
	•	CV parsing and automatic data extraction. 
	•	Candidate ranking based on job requirements. 
	•	Suggested interview questions. 
	•	Skills gap analysis. 
	•	Duplicate applicant detection. 
	•	AI-generated shortlist recommendations. 
	•	Predicted suitability score. 
	•	Automated email drafting for candidate communications. 
All AI recommendations should be reviewable by HR before action is taken.

21. KEY SYSTEM RULE
No candidate shall be transferred to the Employee Master Database until:
	•	The offer has been accepted. 
	•	Mandatory pre-employment checks have been completed. 
	•	Required approvals have been obtained. 
	•	HR confirms onboarding. 
This ensures that only approved employees become active in the Seventh Sky HRM system.
